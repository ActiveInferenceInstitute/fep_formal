# FEP_Formal Lean workspace contract

The Lake library name is `FepSketches`; project branding does not rename that
import surface. [lean-toolchain](lean-toolchain), [lakefile.lean](lakefile.lean)
and [lake-manifest.json](lake-manifest.json) own the reproducible Lean/Mathlib
pair and exact dependency revision.

## Source ownership

- `FepSketches/fep_all.lean` is generated from canonical family-owned topic
  bodies by `scripts/_maint_build_fep_all_lean.py`.
- Every formal resource in `src/fep_formal/formal/manifest.py` has a byte-exact
  `FepSketches/` projection generated by
  `scripts/_maint_build_formal_modules.py`.
- Composition leaves own cross-topic proofs; `composed.lean` is their
  import-only aggregate. Scientific relations are authored separately and
  require qualified witnesses, not shared imports.
- Preserve the module-system header, required public or meta imports and
  declaration visibility when regenerating. An import change needs its real
  importing consumers checked, including modules outside the topic aggregate.
- Verifier-owned `_verify_*.lean` probes are temporary. Delete only the probes
  created by that verifier operation; never commit them.

The [generated-tree contract](FepSketches/AGENTS.md) identifies the two
projection owners. Never hand-edit a `.lean` workspace projection.

## Setup, resolution and evidence

Explicit `fep-formal setup` owns dependency acquisition under
`FEP_FORMAL_SETUP_TIMEOUT_SEC`; it checks pins before and after child processes,
preserves the lock and never runs `lake update`. Validation does not acquire
dependencies. A deliberate pin change needs a reviewed migration and new
evidence.

[`_toolchain.py`](../src/fep_formal/verification/_toolchain.py) owns executable
resolution. Explicit `FEP_FORMAL_LAKE_EXE` / `FEP_FORMAL_LEAN_EXE` overrides take
precedence; ordinary discovery prefers the project pin where available.
Receipt validators compare the actual compiler and resolved Mathlib revision
with the declared pair. Availability alone is not pin validation.

A supplied `ELAN_HOME` is respected. Otherwise compiler children use a per-user
temporary home; they receive only the allowlisted environment and required
paths, keeping provider credentials out of compiler subprocesses. This changes
child configuration, not filesystem permissions.

Per-topic verification is serial around the shared Lake build tree. Parallel
work needs independent workspaces; do not add concurrency inside
`LeanVerifier.verify_batch`. Aggregate build, canonical orphan compilation,
exact-roster topic verification and declaration/axiom auditing retain separate
acceptance scopes. None establishes Hermes/OpenGauss or scientific acceptance.

Use the [root execution contract](../AGENTS.md#execution-contract) and
[required-check inventory](../AGENTS.md#required-checks) for commands; the
[workspace guide](README.md) explains maintenance order.
