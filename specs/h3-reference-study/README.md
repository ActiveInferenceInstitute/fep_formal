# H3.G0: continuous carrier eligibility

The eligibility validator is implemented and tested. The retained H2.7
terminal record currently validates; no actual G0 study metadata or acceptance
record exists here, and no H3.0 protocol is frozen. Each eligibility check
revalidates the complete H2 terminal contract.

The owner is the source-bound G0 record described in
`docs/design/fep-research-program/horizon-3-scientific-case-study.md:90–123`.
The validator reads H2 evidence and the exact existing Fin4/conditioning
declarations. It adds no Lean module, repairs no proof, and changes no carrier.

Run `uv run python specs/h3-reference-study/eligibility.py --project-root .
--metadata output/h3-pre-outcome-metadata.json`. Omit `--output` for a read-only
check; an explicit output must be a new file. The metadata object has exactly:

```json
{
  "schema_version": 1,
  "branch": "continuous",
  "outcomes_accessed": false,
  "pre_outcome_basis": "Actual recorded license, variable, unit, sampling and intervention metadata",
  "finite_branch_considered": false
}
```

This is a schema illustration, not recorded scientific evidence. The recorded
G0 instance of this schema is `specs/h3-case-study/pre-outcome-metadata.json`
(selection recorded at `specs/h3-case-study/README.md:32`). Supply actual
pre-outcome observations. No protected outcome, approval, or terminal receipt is
generated by this command. Finite branch consideration fails closed pending a
separate review binding the accepted H1.8 terminal and preserved first-merge
no-go/repair evidence; it never silently substitutes that carrier.

Successful G0 can open H3.0 protocol preparation only. A frozen
`preregistration.yaml`, H3.1 implementation, empirical analysis, and claims of
physical dissipation remain outside this implementation scope.
